# 模块计划

模型：GPT-6.1 Sol，Ultra。每次只推进用户指定的一个模块。模块是交付边界，不是五小时工作时长；用量需实测，未知故障可独立拆成 Rxx 修复任务。

| 编号 | 范围 | 验收标准 |
|---|---|---|
| M00 | 工程基础、版本/规则/接口、交接文档 | 关闭编辑器后编译成功，工程和空地图能重新打开 |
| M01 | 空场景首次 Windows Development 打包 | 脱离编辑器启动和退出成功 |
| M02 | 少量图片/动画/音频导入试验 | 透明度、帧序、缩放和音频正确 |
| M03 | 完整资源导入及清单 | 无缺失引用，重复导入不产生重复资源 |
| M04 | 摄像机、草坪、网格命中 | 格子定位正确，边界外输入被过滤 |
| M05 | 阳光生成、掉落、收集、余额 | 每个阳光仅计入一次 |
| M06 | 选卡、种植、预览、扣费、冷却 | 正常放置及余额/占位/越界反馈正确 |
| M07 | 按行僵尸生成和移动 | 多行移动正确，速度不依赖帧率 |
| M08 | 射击、子弹、伤害和死亡 | 单行种植到消灭僵尸的流程可玩 |
| M09 | 僵尸攻击植物 | 接触后攻击、植物死亡后继续，格子释放 |
| M10 | 向日葵生产 | 阳光可拾取，植物死亡/铲除后停止生产 |
| M11 | 坚果场上静态图和防御 | 使用独立角色图，能阻挡并受伤 |
| M12 | 铲除与取消 | 有效目标可铲除，取消和空地输入正确 |
| M13 | 波次、进度、胜负 | 清空所有波次胜利，突破防线失败 |
| M14 | 主菜单、开始、重开、结算 | 流程完整，多次重开无残留对象/计时器 |
| M15 | 暂停/继续及输入 | 战斗计时停止，菜单可操作，恢复正确 |
| M16 | 音乐与事件音效 | 触发正确，切换/重开无叠播 |
| M17 | 音量/静音/保存 | 即时生效，重新启动后保留 |
| M18 | 操作说明、提示、窗口适配 | 界面可读，缩放后命中准确 |
| M19 | 综合验收 | 已实现功能的回归清单通过，缺陷有记录 |
| M20 | 最终 Shipping 包 | 打包版五项交互和胜负流程全部通过 |
| M21 | 作业说明与演示材料 | 可按文档打开、构建、运行和答辩 |

五项交互：M06 选卡种植、M05 阳光拾取、M12 铲除、M15 暂停恢复、M17 音量设置。老师是否接受“五项功能”仍需用户确认；当前没有五种输入模态的要求。

## 执行与用量

- 开始、主要验证前、结束时读取账户额度；其他聊天和子代理共享额度，消耗差值只是观察值。
- 初始目标是每模块消耗不超过完整五小时窗口约 40%，预留至少 30% 做验证和交接。这不是保证值。
- 不足以启动完整模块时，先明确拆分边界，再实施更小的交付；不把未验证工作标为完成。
- M00/M01 用于校准。每次完成只保留简短状态、接口变化、验证证据和下一步，避免上下文无限增长。
- 编译/资源/兼容故障若明显超出模块范围，按问题单独拆为 Rxx；不得把 M19 当作所有未知问题的兜底。
