# 架构约定

## 已选技术与边界

- UE 5.8.2，Windows x64，C++ 项目。
- Paper 2D 精灵 / Flipbook 和正交摄像机；UMG 界面；通过 UPROPERTY/UFUNCTION 暴露设计参数。
- 单机关卡，无网络、账号、外部服务或第三方付费插件。
- M00 只建立运行模块、空 GameMode / PlayerController、空地图和构建/自检脚本。

## 后续模块的职责合同（规划，M00 不实现）

| 责任 | 约定 |
|---|---|
| 关卡状态 | GameMode 维护准备/运行/暂停/胜利/失败，关卡只允许一次结算 |
| 输入 | PlayerController 将鼠标/键盘事件转为选择、放置、收集、铲除等意图；UI 输入不能误触草坪 |
| 网格 | 用整数行列识别格子；集中管理占用、有效性和世界坐标转换，不靠图片颜色判断 |
| 经济 | 单一阳光余额所有者，提供能否支付/扣除/增加接口；UI 仅展示和发请求 |
| 植物 | 类型/费用/生命/冷却等使用配置数据；移除统一清理计时器并释放网格 |
| 僵尸 | 行号、生命、移动/攻击状态；同排目标判断，不做跨排攻击 |
| 子弹 | 同排命中，命中最多结算一次伤害，销毁后无残留回调 |
| 时间 | 战斗使用可暂停的游戏时间；UI 和暂停菜单不依赖被暂停的战斗计时器 |
| 音频 | 统一控制音乐/音效音量，关卡重开不创建重复音乐实例 |
| 重开 | 销毁/重置对象、波次、余额、网格和计时器，清除旧选择状态 |

先落地简单职责，随对应模块增加类和接口，不在 M00 预先创建所有系统。

## 内容与版本管理

- 空启动地图约定：`/Game/Maps/M00_Bootstrap`。
- 后续地图和数据使用 `/Game/Maps`、`/Game/Data`；原型导入资源分类存放。
- 资源命名与数值字段在 M02/M03/M04 落地；帧文件必须按数字顺序而非字符串顺序排列。
- 源码、配置、必需 `.umap`/`.uasset`、脚本及文档入库；编译产物、派生缓存和完整运行包不直接入库。
- 当前原型目录不在 Git 仓库内，M00 工程必须能够在没有该目录时构建。

## M04 已落地的网格入口

`/Game/Maps/PvZ_Lawn` 的一个 `AMyPvZBoard` 持有背景、正交相机和 `FMyPvZGridLayout`。PlayerController 将游戏视口像素经实际相机投影转为整数格子，并广播 `OnGridCellPressed(Row,Column)`；后续系统使用此事件与 Board 转换接口。坐标、半开边界及诊断反馈见 `GRID.md`。占用、经济和种植仍由对应后续模块实施；默认启动地图暂保留 M00_Bootstrap。
